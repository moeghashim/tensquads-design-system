The chat is play mode's whole surface: it is how you talk to the workflow you just drew. It lives in a 480px `panel` on the right of the canvas (`inspector-width` plus room for prose) and fills a page when used on its own.

Three parts, top to bottom. A top row with a ghost **New chat** button in `text-secondary`. A scrolling **log** (`role="log"`, `aria-live="polite"`) with 12px between entries: the user's message is a `primary-soft` pill on the right at 16/24, at most 85% wide; every step the run touches is a row on the left — the kind's 16px glyph, the step name at 16/24 weight 500, an optional status word in `text-tertiary` (`routed to Recipe`, `blocked` in `danger-text`), the response id in `mono` 12px indented under it, and the model's reply in `text-emphasis` under that, indented 24px to align with the name. While a step runs its glyph is a 14px `aui-spinner`. With no entries the log shows the empty state: a 32px `primary-soft` tile with the wand glyph, "Preview your agent", "Prompt the agent as if you're the user."

The **composer** is a `surface` card with 24px corners and a hairline ring, pinned to the bottom with 8px around it. The textarea sits on top (16/24, grows to 160px, `↵` sends and `⇧↵` breaks the line); the bar under it has an attach button on the left and a 32px `primary-solid` send pill on the right. Send is disabled on empty text (`alpha-12`), and while the run is busy it becomes **Stop**: the same pill with a 10px square.

Replies are markdown rendered by the consumer and passed as an element; the `aui-msg__reply` styles cover paragraphs, headings, lists, inline and block code and links. **Do**: keep every step the run touched in the log, even silent ones — it is how people see routing happen. **Don't**: put the agent's reply in a bubble; only the user gets one.
